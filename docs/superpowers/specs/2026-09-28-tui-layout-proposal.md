## 设计方向

采用「对话主区 + 右侧协作栏 + 就地输入」作为默认布局；专注模式收起侧栏。
将 pi 的低干扰对话和编辑体验，与 OpenCode 的主区 / 右侧信息栏组织结合。
agentmux 的新增重点是任务辨认、接收者确认、跨 Agent 接力和待处理事项。

## 默认布局：协作模式

```text
 agentmux   agentmux / auth-fix                  2 running · 1 needs input
 ──────────────────────────────────────────────────────────────────────
 修复登录态刷新                               │ 协作  改动  上下文
 Claude Code · working                        │
                                              │ auth-fix · shared
 you                                          │ › ◐ 修复登录态刷新
 修复过期后的刷新逻辑，保持接口不变。           │     Claude Code · working
                                              │   ! 验证刷新边界
 Claude Code                                  │     Codex · needs input
 问题出在同时触发的刷新请求……                 │   ✓ 梳理认证调用链
                                              │     pi · done
 ▸ read  src/auth/session.ts                   │   ◐ 补充回归测试
 ▾ edit  src/auth/session.ts   +12 -4           │     OpenCode · working
   - return refreshToken()                    │
   + return pendingRefresh ??= refreshToken()  │ 待处理 1
                                              │ Codex · 请求运行测试
                                  ↓ 最新      │
 ── → Claude Code / 修复登录态刷新 ─────────── │
 > 加上并发刷新测试。                          │
                                              │
 Enter 排队 · Alt+Enter 换行 · / 命令           │
 ──────────────────────────────────────────────────────────────────────
 auth-fix · agentmux/auth-fix        Ctrl+P 任务 · Ctrl+B 侧栏 · F1 帮助
```

- 顶部是项目 / 工作区路径与全局任务状态；只有待处理 / 错误需要强调。
- 中间主区只显示当前会话，标题采用任务名；Agent 名、状态放在次行。
- 右侧默认「协作」，按工作区分组任务；当前工作区展开，其他组可折叠。
- 「改动」显示当前会话涉及文件；提供工作区范围切换，避免混淆个人与共享修改。
- 「上下文」展示工作区路径、分支、共享黑板摘要和已引用内容；正文按需展开。
- 输入框只属于当前会话主区，不横跨侧栏，减少“向所有 Agent 发消息”的暗示。
- 页脚常驻内容控制在一行；窄屏缩短提示，完整帮助进入 F1 / `/help`。

## 专注模式与尺寸

| 终端宽度 | 布局 |
| --- | --- |
| ≥ 160 列 | 主区 + 28–32 列协作栏；审阅时主区可拆为对话和 diff，每区至少 56 列，否则退回单检查视图。 |
| 110–159 列 | 主区 + 28 列协作栏；diff 暂时占主区，关闭回到原会话。 |
| 80–109 列 | 默认主区铺满；Ctrl+B 临时打开 28 列侧栏覆盖层，Esc 关闭。 |
| < 80 列 | 全宽对话；任务选择和检查视图全屏切换；保留接收者与待处理入口。 |

专注模式可在任何宽度手动开启，使用完整主区；顶部仍保留“2 运行 / 1 待处理”的短入口。
高度不足 24 行时缩短标题留白，编辑器最低 1 行；不足 16 行时改为紧凑呈现。
原型的浏览器宽度仅用于演示收纳行为，实际 TUI 按终端 cell 数判断。

## 消息、工具与视觉

- 减少包住每个面板的完整框线。优先使用一条分隔线、缩进和局部背景区分层级。
- 用户消息可用浅底或左侧短竖线；回复采用普通正文，角色名只在消息起始出现。
- 工具默认一行：状态、动作、路径 / 命令、耗时（有数据才显示）；Enter 展开完整结果。
- 思考块默认折叠，避免推理文本抢占回复空间；提供可见展开入口。
- 支持标题、列表、代码块等基本 Markdown；diff 使用 +/- 与颜色同时编码。
- 任务选中行使用柔和背景 + `›`，避免整行高反差反色；运行 `◐`、等待 `!`、完成 `✓`、错误 `×`。
- 保留灰蓝为焦点色，暖黄为等待、鼠尾草绿为完成、赤陶红为错误。不要给每个 Agent 随机配色。
- 深色 / 浅色 / terminal-default 三种主题；重要文本对比度目标 ≥ 4.5:1。
- 只用终端可实现的单元格背景、文字、框线，不依赖阴影、玻璃效果或任意像素圆角。

## 输入与键盘模型

默认可以直接输入，取消必须先按 `i` 的门槛；可后续提供 Vim 操作偏好。
`j/k/n/q/x` 在编辑器中均为普通文字。只有焦点在列表 / 浏览区时启用对应导航。

| 操作 | 建议快捷键 / 入口 |
| --- | --- |
| 任务切换器 | Ctrl+P，按标题 / Agent / 工作区过滤，Enter 选择 |
| 显示 / 隐藏侧栏 | Ctrl+B |
| 编辑器 → 主区 → 侧栏焦点循环 | F6 / Shift+F6；Tab 留给编辑器补全或列表控件 |
| 发送 | Enter；当前会话忙时明确显示“排队”，不暗示即时干预 |
| 换行 | Alt+Enter；终端支持增强键盘协议时也支持 Shift+Enter |
| 外部编辑器 | Ctrl+G（实现时恢复终端状态，再返回草稿） |
| 命令 / 帮助 | 输入 `/` 打开命令；F1 随时查看帮助，浏览态 `?` 同义 |
| 回看 | PageUp / PageDown / 鼠标滚轮；浏览态 End 恢复跟随；编辑器内 End 仍移动行尾 |
| 展开工具 | 主区选中块后 Enter；Ctrl+O 批量展开 / 收起工具 |
| 中断当前任务 | Esc 先关闭局部菜单 / 离开输入焦点；浏览态 Esc 发出中断；有明确“中断”命令入口 |
| 退出 TUI | `/quit` 或命令面板，明确提示后台会话继续运行 |

排队默认含义：此会话当前 turn 完成后发送下一条消息；队列可查看、编辑、撤回，建议由 daemon 持有以跨 TUI 重连保存。
pi 的 steering / follow-up 能力不直接假定所有 adapter 都支持；只有明确能力协商后才增加“立即引导”动作。
多行粘贴使用 bracketed paste，绝不按每行回车逐条发送。

草稿、输入历史、附件引用、滚动位置、展开块与队列均按 session_id 隔离。
发送期间先保留草稿副本，确认服务端接收后清理；失败时可恢复。

## 多 Agent 的关键操作

### 任务身份

每条会话优先使用用户可修改的任务标题，初始可取首条 prompt 的简短首行。
Agent 名称是执行者信息，短 ID 放入详情。同名任务时追加工作区 / 短 ID。
状态摘要由真实事件导出；不虚构进度百分比、token、成本或 ETA。
有模型 / 用量数据才在详情显示，没有就省略。

### 接力

选中消息 / 工具结果 → “引用到…” → 目标任务选择器 → 目标会话草稿中的引用行。
引用行包含来源 Agent、任务标题和事件范围，可展开、删除。
默认只准备草稿，用户发送后才投递。接收者始终显示在编辑器顶端。
输入中的 `@` 打开引用选择（文件 / 会话消息分组），不在普通打字时立即切走。

### 待处理权限

所有请求进入独立队列，以 session_id + request_id 标识，不覆盖旧请求。
其他 Agent 的请求只增加协作栏和顶栏提示，不抢走编辑器焦点。
主动打开请求后，主区显示工具名、命令 / 路径、来源任务及明确选项。
允许 / 拒绝仅在该请求视图获得焦点时生效；不能将正在输入的字母解释为批准。
回答期间显示处理中；成功移除对应请求；失败保留并给出重试。

### 共享修改

按会话文件活动展示“谁涉及过该文件”；工作区 diff 是当前文件系统的总改动。
无法可靠归因的 diff 不标为某个 Agent 独占产物。
多个会话涉及同一文件时提示“多人涉及”，不直接宣称已发生冲突。

## 空态、失败与性能

- 无项目：主区直接提供注册本地项目入口，随后选择 / 创建工作区和 Agent。
- 无可用 Agent：显示已配置但不可用的条目及检查说明，不只显示空列表。
- 断线：全局连接状态保留，草稿可继续编辑，发送不可用；提供重连入口。
- 会话失败：就地保留错误摘要、日志入口和恢复动作，避免整页弹窗。
- 后台高频输出只刷新相关行；用户浏览历史时不跳动；按消息 / 工具块缓存与虚拟滚动。
- 旧历史从持久化日志分页获取；不能以“只保存当前可见行”替代历史可访问性。

## 审核问题修复

- 历史分页同时限制事件数量与 JSON 字节数；单条超大事件以及超大待处理权限详情，通过 `session/event/read` 按 UTF-8 边界分块，SDK 完整重组，不静默截断。
- 恢复排队 / 失败消息前，保留当前草稿及引用，可从消息恢复入口取回。
- diff 查询携带递增请求标识；关闭、切换、打开其他操作后，迟到的响应不再覆盖当前视图或权限窗口。
- 文件是否受版本控制同时检查索引与 HEAD，支持已暂存删除的文件。
- 键盘焦点和鼠标使用同一套遮挡规则；窗口变化后旧焦点不能激活隐藏控件。
- 输入渲染、鼠标定位、上下方向键共用终端单元格布局，包含中文、emoji、Tab 和自动换行。

## Close panel 后输入卡死修复（2026-09-29）

复现：关闭右侧栏后，向真实 PTY 连续输入 1500 条鼠标移动报告，再输入普通文字。
原版本超过 15 秒仍不显示文字，输入写入端阻塞；主循环仍运行，终端读取线程停在 `epoll_wait`。
Crossterm 0.29 的默认 Unix mio 后端读取 1024 字节后提前返回事件，没有读到 EAGAIN；缓冲区中剩余输入可能无法再次触发边沿通知。

- 启用 Crossterm 的 `use-dev-tty` 特性，切换到基于 `poll` 的 Unix 输入后端，持续处理尚未读完的数据。
- 过滤鼠标移动、拖动、释放及按键释放事件；界面只在状态变化时重绘。仅减少重绘不足以修复上述读取停滞。
- Close panel 使用明确的关闭动作，清理侧栏焦点和引用选择，并回到输入模式；顶部 Show panel 可重新打开。
- Resume 只对已结束或失败的任务展示；权限请求按会话区分，任务结束时清理旧请求；迟到的新建任务响应保留用户当前选择和草稿。

## 终止会话恢复并发送（2026-09-29）

用户截图中的 Pi 会话在 daemon 重启后处于 `Error("daemon restarted")`。旧版仍展示 Send，但发送时退回草稿并提示输入 `/resume`，使鼠标用户无法直接完成发送。

- 终止会话的主按钮改为 Resume & send，Enter 执行相同操作；Resume 单独点击仍只恢复 Agent，不发送草稿。
- 按会话记录正在恢复的状态，阻止重复恢复；提交消息先排队，等待恢复 RPC 成功且会话 Ready 后才发送。
- 恢复失败或连接失败会保留提交消息，不覆盖用户新写的草稿或其他任务的草稿；daemon 已断开时单独提示重新连接。
- 恢复会启动新的 adapter 会话，不承诺恢复 provider 端的对话记忆。历史展示行为已由下方“重启对话边界”修订。

验证：105 项 TUI 测试通过，包含恢复响应与 Ready 事件的两种先后顺序、失败恢复、重复点击和断线。真实 PTY 在 120×30、80×24、40×16 下重启隔离 daemon，验证一次点击恢复并且只发送一次，随后中文 Enter 发送正常；现有用户 daemon 与会话未被测试修改。

## Pi 斜杠命令与补全（2026-09-29）

原输入框将所有 `/...` 消费为工作台命令，且多 Agent 共享上下文会在命令前插入文字；两处都阻止 Pi 按斜杠命令处理输入。Pi 运行在 RPC 模式，原生终端的菜单不会自动出现在工作台。

- 输入 `/` 显示建议，支持键盘上下选择、Tab 补全、Enter 执行和鼠标选择。
- 新增 `session/pi`，仅开放命令发现、模型/思考级别查询与设置、压缩和会话信息等明确的 RPC 操作。修改操作与普通 prompt 共用会话互斥，不会跨 Agent 路由。
- `/model` 和 `/thinking` 显示 Pi 返回的实际选项，`/settings` 显示当前模型、思考级别和自动压缩设置；支持 `/compact`、`/session`、`/name`。`/new` 在同工作区创建新 Pi 任务。
- 从 `get_commands` 加载扩展、模板和技能建议；命令文本保留开头 `/`，不注入共享上下文。带跨会话引用的斜杠命令会提示先发送引用，不静默丢弃。
- 输入 `/mux <command>` 执行工作台命令，避免 `/new`、`/resume`、`/thinking` 名称冲突；现有鼠标按钮不改变含义。
- Pi 原生登录、会话树等界面尚未嵌入；相关命令显示限制，扩展 UI 对话协议仍未接入。迟到的查询结果不会重新打开已关闭的选择框。

验证：工作区 267 项测试通过、2 项忽略；`tui/tests/pi_commands_pty.py` 在隔离 daemon 与 fake Pi 上验证 120 / 40 列的命令发现、补全、模板转发、模型/思考级别/设置/压缩和本地命令。另以本机 Pi 的独立无持久会话进程验证 `get_state`、`get_commands`、`get_available_models`、`get_available_thinking_levels` 真实返回，无模型请求。

部署需同时更新 daemon 和 TUI；旧 daemon 会对 `session/pi` 返回 method not found。重启 daemon 会结束当前 adapter 连接，历史记录保留，恢复时使用新的 adapter 对话。

## 启动时重启后台（2026-09-29）

新增 `agentmux-tui --restart-daemon`：进入终端原始模式前请求后台退出，等待旧 socket 移除，再启动服务并加载界面。普通启动保留已有后台；没有后台时两种启动方式都会自动拉起服务。关闭请求和等待退出均有超时，不会无限卡在启动界面。

`server/status` 增加实际数据目录与配置文件的绝对路径，重启时沿用这些路径；兼容旧后台缺少这些字段的情况，此时采用环境变量或默认值。运行中的 agent 连接会结束，持久任务可以通过 Resume 或 Resume & send 恢复。

验证：客户端 10 项、服务端 8 项、TUI 111 项测试通过，另有 2 项忽略；Clippy 与构建通过。真实 PTY 使用该启动参数验证 120×30、80×24、40×16 的关闭面板、输入、恢复并发送与退出流程。已按用户要求重启实际 daemon，确认新版接口生效。

## 重启对话边界（2026-09-29）

修正 Resume 创建全新 adapter 对话、界面却继续拼接整个任务历史的不一致行为。恢复成功持久化 ConversationStarted 事件；历史 API 返回最新对话边界和本次对话标题，界面按边界显示聊天并重置标题、滚动位置和输入历史。旧版本的恢复日志也识别为对话边界。

旧日志继续保留供引用使用。恢复失败不清空当前聊天；其他 agent、未发送草稿不受影响。旧历史页迟到不会覆盖新标题，边界不在当前分页内时依然生效，重开 TUI 也保持该边界。

后续修正：上一版只在 Resume 成功后切换聊天，遗漏了用户通过 `--restart-daemon` 进入界面、尚未 Resume 的场景。现在持久化的 `Error("daemon restarted")` 状态事件也作为显示边界，立即隐藏旧聊天、旧标题和旧的重启错误行，空白聊天显示 New conversation。此时 adapter 尚未连接，用户可直接输入并按 Enter 恢复并发送。测试在点击 Resume 前检查此行为，不再仅验证 Resume 之后。

该补充修复通过 10 项客户端与 116 项 TUI 测试（另 2 项忽略），以及三种窗口尺寸的真实 PTY 验证。另用新 TUI 连接实际用户后台，只读取并渲染已有会话，确认未点击 Resume 时旧标题、旧回答和重启错误行均隐藏；未发送模型消息。

## 状态去重与流式丢片段修复（2026-09-29）
