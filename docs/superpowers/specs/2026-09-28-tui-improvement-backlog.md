# TUI 体验优化记录

日期：2026-09-28
状态：已记录；五项主要交互已随新版 TUI 实施，边界见布局提案的实施记录
依据：当前 `tui/src/ui.rs`、`input.rs`、`app.rs` 的源码评审；以下优先级为设计建议。

| 编号 | 优先级 | 当前问题 | 优化方向 | 验收场景 |
| --- | --- | --- | --- | --- |
| TUI-01 | P0 | 输出跟随最新内容，没有正常的历史滚动入口；长内容截断后无法展开。 | 支持翻页、滚轮、历史浏览、暂停自动跟随和回到底部；截断内容可展开。 | Agent 持续输出时仍能阅读旧消息；返回底部恢复跟随；长工具输出可完整查看。 |
| TUI-02 | P0 | 输入框只有一行，只能末尾追加和退格，不能移动光标编辑。 | 多行编辑、光标移动、输入历史、完整粘贴、自适应高度；按终端显示宽度处理中文与 emoji。 | 粘贴多行任务不会误发；能修改句中内容；切换会话后草稿仍归属于原会话。 |
| TUI-03 | P1 | 会话以 Agent 名称和随机 ID 为主，多个同类 Agent 难以区分任务。 | 任务标题优先，Agent 名和 ID 次要；展示执行状态、待处理事项和未读活动。 | 同时运行多个相同 Agent 时，可以根据任务名选中正确会话，并确认提示词接收者。 |
| TUI-04 | P1 | 侧栏固定 36 列，窄屏占比过大；状态栏快捷键过长。 | 自适应、可折叠侧栏；按宽度收纳辅助信息；常用快捷键就地展示，完整帮助放入 `?` 或命令面板。 | 80 列仍能舒适阅读和输入；120 列可展示任务导航；宽屏可额外检查上下文。 |
| TUI-05 | P2 | 文件面板仅列路径，替换消息区后无法直接审阅改动。 | 文件可选择并进入 diff；宽屏支持会话与改动并排，窄屏以临时检查视图呈现。 | 从文件列表打开可滚动的改动视图，关闭后恢复原会话阅读位置。 |

后续布局设计见 [TUI 新布局提案](2026-09-28-tui-layout-proposal.md)。本记录保留五项评审原意，具体交互由提案进一步定义。
