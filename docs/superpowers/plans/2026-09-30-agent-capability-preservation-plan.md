# Agent 能力完整性与原生托管修正计划

日期：2026-09-30
状态：第一阶段已完成验收；原生托管、历史入口与旧会话接管实施中

## 产品原则

agentmux 是管理现有 Agent 的壳，不是功能裁剪版 Agent。统一工作区、进程生命周期、切换、权限与协作入口，不强求统一所有 Agent 的交互。

用户再次确认的优先级：**首先让多个 Agent 在框架内完整、正常运行；其次才是多个 Agent 共享会话空间。** 原生运行、独立终端、历史恢复与重连是 P0；共享上下文与接力不能成为 Agent 正常使用的前提。

- 原生托管保障功能完整性；结构化接入提供统一聊天、工具记录、引用接力等增强体验。
- 普通 `/...` 属于当前 Agent；工作台命令使用 `/mux ...`。工作台按钮仍执行工作台操作。
- 恢复原生对话与启动新对话是不同操作。恢复失败不得静默新建，不得用事件日志回放冒充原生上下文恢复。
- 原生 Agent 是会话内容、分支、配置与插件状态的权威来源；agentmux 持久保存原生会话定位信息及自己的管理信息。
- 单个会话只有一个写入控制者。原生与结构化模式转换必须有明确、可验证的交接协议，不得同时启动两个进程写同一会话。
- 能力按实际 Agent、适配器和版本协商；区分已接入、上游支持但未接入、仅原生可用、上游不支持。

本计划修订 `2026-09-28-agentmux-design.md` 中 v1 排除 PTY 透传的边界。原生入口现在是必做项，不再是可无限延期的附加功能。

## 第一阶段：恢复语义与命令归属

- [x] 持久保存 Pi 会话文件，并兼容已有 SQLite 数据与旧客户端。
- [x] Pi 重连通过 `switch_session` 恢复原会话；扩展取消、文件丢失、协议错误必须显式失败，保留原定位信息。
- [x] ACP 根据初始化能力接入 `session/load`；不支持恢复时明确报错，不退化为新建。
- [x] 首次创建失败且从未获得原生会话定位信息时，允许重试首次创建；不将已有对话重建为新对话。
- [x] 成功恢复不清空聊天、标题或原生会话 ID；daemon 重启只影响连接状态，不抹掉历史展示。
- [x] 所有已选 Agent 的普通斜杠命令不再被工作台同名命令抢占，`/mux ...` 为工作台命令空间。
- [x] 工作台 Resume 提供当前原生对话恢复入口；不将 Pi 原生 `/resume` 历史浏览命令错误地映射为当前会话恢复。
- [x] 更新 README、旧设计与实施记录，标明当前真实支持范围。
- [x] 覆盖数据库升级、恢复成功/失败/取消、daemon 重启、能力缺失、命令冲突、草稿与历史保留的回归测试。

第一阶段当前边界：Pi 原生 `/resume` 历史选择器、原生 PTY 界面、扩展自定义终端组件尚未接入。旧 Pi 记录若缺少原生文件路径，不会通过猜测或新建替代对话来“恢复”；历史仍可读，原生文件定位/接管属于后续工作。ACP 恢复受实际适配器 `loadSession` 能力约束。

已验证：工作区 323 项测试通过、3 项手动测试忽略；工作区构建、Clippy（`-D warnings`）、格式与 diff 空白检查通过。真实 Pi 0.87.1 在独立工作目录、数据目录与配置目录中验证 daemon 重启后原生 ID、文件和消息上下文保持一致，无模型调用。

真实终端回归：`close_panel_pty.py` 在 120x30、80x24、40x16 验证恢复并只发送一次、中文输入和重开历史；`multi_agent_pty.py` 在 40x16、80x24、120x30、160x40 验证添加、路由、草稿、命名和重开；`pi_commands_pty.py` 在 120/40 列验证命令控制，超过 1,000 条 Unicode delta 的补齐、去重以及 1,800 行思考与代码历史滚动。长输出测试按本次 turn 的起始 seq 校验，不再依赖 Resume 清空历史。可选真实 Pi 验证脚本为 `core/tests/pi_native_resume_smoke.mjs`，执行方式见文件头。

部署边界：仅构建并测试新二进制，没有重启用户实际 daemon 或修改用户原生会话。旧 Pi 原生文件路径的定位/接管和原生 PTY 入口完成前，不通过自动重启强行迁移现有会话。

## 第二阶段：原生托管基线

- [ ] 新建 Agent 时可选择原生托管；为各 Agent 配置原生启动命令，不能拿 ACP 适配器命令代替。
- [ ] daemon 持有 PTY 与进程，TUI 退出/重连不结束 Agent；多个 Agent 保留独立终端状态。
- [ ] 使用成熟 PTY 与终端状态解析库，不自行实现终端转义协议，不通过解析屏幕文字伪造结构化事件。
- [ ] 主区呈现原生终端，支持输入、粘贴、焦点、窗口缩放、滚动与重连快照；明确工作台快捷键与原生按键边界。
- [ ] 原生 `/resume`、登录、插件菜单、会话树、交互审批等留在原生界面执行。
- [ ] 对单写入所有权、断线后的控制租约、敏感输入与终端日志持久化定义明确策略。
- [ ] 桌面/窄屏真实 PTY 验证中文、鼠标、键盘协议、终端查询、图像支持范围与重开状态。

## 第三阶段：结构化能力扩展

- [ ] 为各适配器暴露实际能力清单及版本，不将共同最小能力作为所有 Agent 上限。
- [ ] 浏览与加载 Agent 原先创建的会话，不限于 agentmux 自建会话；按工作目录和 Agent 隔离。
- [ ] Pi 扩展 UI 请求/响应闭环，支持取消、超时、断连与跨会话路由；自定义组件仍走原生模式。
- [ ] 接入模型/模式、附件、压缩、分支/fork、导出、steering/follow-up 等能力，逐项验证原生语义。
- [ ] 评估 Codex 官方 App Server 与其他 Agent 专属接口；不强制所有 Agent 走 ACP。
- [ ] 仅在原生会话可互通的 Agent 上提供受控模式切换；否则明确不同模式的会话边界。

## 验收标准

1. 同样的 Agent、配置和工作目录，核心功能在 agentmux 中仍可用；未结构化接入的功能有可用原生入口。
2. 恢复会话后，模型继续使用原对话上下文，不创建替代对话，不以日志注入假装恢复。
3. 恢复失败保留历史、草稿与原生定位信息，不对其他 Agent 产生影响。
4. daemon/TUI 生命周期与原生会话内容分别管理；任一会话只有一个写入控制者。
5. 原生模式与结构化模式分别报告兼容范围，不提前宣称功能完整。
